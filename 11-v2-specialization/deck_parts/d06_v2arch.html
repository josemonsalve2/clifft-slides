6

V2: the architecture

Every rule below exists because V1 violated it. The chapter is short because the design is — one rule, one shared library, one call per instruction.

6.1  The one rule, stated precisely

V1's disease was unrolling the operand sequence. The naive lesson — "don't unroll anything" — is wrong, and would give up the entire specialization opportunity. docs/v2/V2.md:104-132 is precise about three different loops with three different rules:

looprulewhy
over shotsALWAYS a runtime loopshots are data; a persistent kernel with work-stealing pulls them
over the bytecodeALWAYS a runtime loop*the operand sequence is data; unrolling it is the disease
over amplitude groupsstays a loop, but bounds/constants may specializeat rank 10 that is 256–512 groups; flattening reinstates the bloat
the 2×2 / 4×4 butterflyfully unrolleda constant 4–16 multiply-adds; no size risk
The asterisk is the whole invention. V2 does not unroll the bytecode loop — it removes it, by emitting one call per instruction instead of one block. The distinction sounds like hair-splitting and is the entire result: a call site is O(1) IR regardless of what the callee does.

The three loops

V1: the middle loop becomes code
16,432 instructions → 16,432 blocks → 19.9 MB of IR → no binary.
V2: the middle loop becomes a call sequence
16,432 instructions → 16,432 call sites → a kernel with vgpr_spill = 0. The bodies are shared, so the code the optimizer sees is bounded by the opcode set, not by the circuit.

6.2  One operand library, compiled two ways

The substrate is v2_ops.h + v2_ops_body.inc: every opcode body as a static inline function taking its operands and the pre-op active_k by value.

static inline void v2_op_array_cnot(V2State* st, CV2Complex* v,
                                    u32 active_k, u32 a1, u32 a2);
static inline void v2_op_meas_dormant_static(V2State* st, u32 axis,
                                             u32 slot, u32 flags);

That signature is the whole trick. The same source serves two consumers:

the interpreter — coop_interpreter.c
v2_op_array_cnot(st, v, st->active_k,
                 in.axis_1, in.axis_2)
passes runtime values loaded from the bytecode array and from state.
the specializer — v2_specializer.cc
v2_op_array_cnot(st, v, 8u, 2u, 5u)
emits the same call with literals. Same callee, same arithmetic, different argument provenance.
Byte-exactness is by construction, not by testing. The bodies are the same bodies. This directly retires V1's duplication tax (§5.6).

The tier dimension: parameterize cooperation, not arithmetic

v2_ops.h:128-152, verbatim with the barrier body elided to §11.2:

#ifdef V2_REGISTER
#  define V2_STRIDE 1u
static inline u32  v2_tid(void)     { return 0u; }
static inline void v2_barrier(void) {}            // no cooperation, no barrier
#  define V2_REDUCE2(T, L0, L1, O0, O1) do { *(O0) = (L0); *(O1) = (L1); } while (0)
#  define IS_OWNER 1
#else
#  define V2_STRIDE 256u
static inline u32  v2_tid(void)     { return __builtin_amdgcn_workitem_id_x(); }
static inline void v2_barrier(void) { /* release fence; s_barrier; acquire fence — §11.2 */ }
#  define V2_REDUCE2(T, L0, L1, O0, O1) coop_reduce2((T), (L0), (L1), (O0), (O1))
#  define IS_OWNER (t == 0)
#endif
V2_REDUCE2 in the register tier is not a stub for "reduction not needed" — it is an assignment. A stride-1 loop over all amplitudes has already accumulated both partial sums into L0/L1, so the cross-lane reduction degenerates to a copy. Same call site, same argument list, two different meanings, zero runtime branch.
Register tier
1 shot/thread, private state, stride 1, reduction is the identity.
Coop / global tiers
256 threads/shot, stride 256, fenced barriers, butterfly reduction.

Note v2_op_expand_t(st, v, 0u, 0u, 1): the third argument is active_k, which the specializer tracks as it walks the program. Every rank-changing case both prints the current *k and updates it (v2_specializer.cc:42-56):

The interpreter must load st->active_k after every rank-changing op; the specializer knows it at emission time. §7.5 measures what that alone is worth — it is the largest of the eight classes.

Three free wins that fall out of "one call per instruction"

Six opcodes collapse to three call sites
OP_FRAME_S and OP_FRAME_S_DAG emit the same call (v2_specializer.cc:35-36); so do OP_ARRAY_S/_S_DAG and OP_ARRAY_T/_T_DAG, differing only in a literal 0/1 dagger flag — which the optimizer then resolves into two distinct specializations of each body.
OP_DETECTOR takes no arguments at all
It emits v2_op_detector();. The detector's work is entirely compile-time in the specialized path — the interpreter's version has to read operands to discover there is nothing to do.
OP_POSTSELECT is the one case that emits control flow
if (v2_op_postselect(...)) return; — a shot that fails post-selection exits spec_body directly, with no flag to test at the next instruction. The interpreter carries that flag for the rest of the program.
35 of the 41 opcodes are handled. The six that are not — the five *_FORCED variants and OP_EXP_VAL — return false, which aborts emission and falls the whole circuit back to the interpreter (v2_specializer.cc:92-93). Unsupported is safe, not fatal.

6.4  The compile pipeline — no MLIR, no HIP

The directory is named mlir/v2/. That name is the only MLIR left in V2. v2_specializer.cc:127 emits a C translation unit; v2_compile_cache.cc:151-176 compiles it with the raw LLVM toolchain:

// 1) C -> amdgcn bitcode.  Flags IDENTICAL to the build-time interpreter pipeline.
clang --target=amdgcn-amd-amdhsa -mcpu=gfx950 \
      -ffreestanding -nostdlib -nogpulib -std=c23 -O2 -ffp-contract=off \
      -emit-llvm -c -o spec.bc spec.c

// 2) link ocml + oclc controls (identical set to ClifftAmdgcn.cmake)
llvm-link -o linked.bc spec.bc ocml.bc ockl.bc \
      oclc_wavefrontsize64_on.bc oclc_daz_opt_off.bc oclc_finite_only_off.bc \
      oclc_unsafe_math_off.bc oclc_correctly_rounded_sqrt_on.bc \
      oclc_abi_version_500.bc oclc_isa_version_950.bc

opt -O2 -o linked.bc linked.bc                                     // 3
llc -mtriple=amdgcn-amd-amdhsa -mcpu=gfx950 \
    -mattr=+wavefrontsize64 -filetype=obj -O2 -o spec.o linked.bc   // 4
ld.lld -shared -o spec.hsaco spec.o                                // 5
No HIP anywhere
Not a source language, not a runtime, not a packaging format. Contrast Hybrid: emit HIP → Clang Offload Bundle → unbundle to get an ELF HSA accepts. V2 targets amdgcn-amd-amdhsa directly and gets a plain ELF from ld.lld.
Wave64 pinned in two places
gfx950 supports wave32. V2 pins wave64 in both the device-library control set and the backend, because the coop tier's V2_STRIDE 256u and V2_RED_WARPS reduction geometry are written for 64-lane waves.
Never on the sampling path
Compilation is cached to disk. A cold compile costs seconds; a warm run costs a file open. §11.4 is what happened when the cache key was wrong.

The flags are identical to the interpreter's — deliberately

v2_compile_cache.cc:155-156 carries an instruction to future maintainers:

Do NOT add vectorize/unroll/fast-math flags that would diverge from the interpreter.
V2: -ffp-contract=off, no fast-math
Without reassociation or FMA contraction, the optimizer cannot legally change a floating-point result. So the specialized kernel and the interpreter agree bit for bit no matter what inlining decisions differ between them.
Hybrid: -O2 -ffast-math
kernel_cache.cc:115. V2 cannot do this, and the reason is §2.4: a 1-ULP difference flips a sampling branch and desynchronizes the PRNG forever. Hybrid got away with it because Hybrid was never byte-compared against the CPU reference.
Compiler flags are part of the correctness contract here, not a performance knob. This is unusual and worth stating plainly: V2 gives up fast-math — a real optimization — to buy an exact oracle, and §5.6 is why that trade is worth it.

The cache key — and the part that already went wrong once

v2_compile_cache.cc:125-127:

std::string ident = csrc + "|" + llvm_bin("clang") + "|" + arch() + "|" +
                    bitcode_dir() + "|" + device_header_ident();
size_t h = std::hash<std::string>{}(ident);
That last term is a repair
The key originally hashed only csrc — the generated C — which is barely half the translation unit. Every v2_op_* body, v2_barrier(), and every tunable constant lives in the included headers.
A header fix therefore produced the same key, and the stale .hsaco plus its stale .gate verdict silently won. §11.4 documents the benchmark run this destroyed.
The fix hashes contents, not mtimes
All three device headers — v2_ops.h, v2_ops_body.inc, device_abi.h — go into the key by content.
Not mtime: mtimes change on every checkout and would defeat the cache for no reason. A content hash changes exactly when the compiled result would.

6.5  The correctness gate

Specialization is a compiler, and compilers have bugs. V2 does not ask you to trust it. v2_kernel.cc:370-398 validates each freshly compiled .hsaco against the interpreter on a shot sample, and persists the verdict to disk:

// The verdict is written to "<spath>.gate" so it is computed ONCE ever (not
// per process) and NEVER re-run during a profiled sample dispatch -- the
// gate's own validation dispatches would otherwise pollute rocprofv3 traces.
std::string gate_path = spath + ".gate";
if (std::FILE* gf = std::fopen(gate_path.c_str(), "r")) {   // disk cache hit
    int v = 0; if (std::fscanf(gf, "%d", &v) != 1) v = 0;
    validated = (v == 1);
} else {                                                     // compute once
    validated = specialized_matches_interpreter(program, spath, spec_sym);
}
if (validated) { load_path = spath; sym = spec_sym.c_str(); }
else spec_sym.clear();                                       // -> interpreter
On failure the circuit silently falls back to the interpreter — and so does a thrown exception anywhere in emission or compilation. This guarantees byte-exactness for every circuit, not just the ones that happened to be tested.

Three gate details that are load-bearing and easy to miss

1.  The verdict caches in three places, not one
An in-process static std::map keyed by circuit shape, then the on-disk .gate file, then the .hsaco itself. The third one exists because "the gate's own validation dispatches would otherwise pollute rocprofv3 kernel traces." A correctness check that perturbs the measurement is a correctness check you stop running.
2.  The key is the circuit shape, not its name
tname + "_r" + peak_rank + "_n" + num_instrs (v2_kernel.cc:366-367). circuit_d5_p0.001 and cultivation_d5 compile to the same coop_r10_n1720 key when their bytecode has the same rank and length — so they share one gate verdict and one .hsaco. That is why §11.1's failure took out a whole family at once.
3.  The gate does not tell you what is wrong, only that something is
Both diagnostics that exist — V2_GATE_VERBOSE, V2_GATE_BISECT — had to be added during §11.2's investigation. A boolean oracle is enough to be safe and not enough to debug.

6.6  The specializer is opt-in — a real hazard when reading benchmarks

getenv("V2_SPECIALIZE")
v2_kernel.cc:358 — unset, V2 runs its bytecode interpreter.
With V2_SPECIALIZE unset, a benchmark measures V2's interpreter against SVM's tuned interpreter and reports what looks like a 2–3× regression.
Why it is opt-in at all
The interpreter is the fallback path and must stay exercised. Making specialization default would mean the un-specialized path only runs on the six unsupported opcodes — and silently rots.
Every number in this deck was produced with it set
§11.4 shows what happens when a stale gate verdict un-sets it for you — the flag is on, the fallback fires anyway, and the run looks like a regression you did not cause.

6.7  The three tier wrappers — and the line that states the thesis

One spec_body, three wrappers (v2_specializer.cc:172-225). spec_body takes 21 parameters; the first five are tier-dependent, the remaining 16 identical across tiers — emitted once into a const char* fwd and reused verbatim, so the tier choice cannot accidentally change what the body receives.

Every wrapper opens with the same line:

(void)peak_rank; (void)num_instrs; (void)instrs; (void)total_meas_slots;
Those four kernel arguments are what the interpreter runs on: the bytecode pointer, its length, the rank, and the measurement-slot count. The specialized kernel takes them — the kernarg layout must stay identical, one dispatch path serving two kernels — and then discards all four.

That single line is the specialization thesis written into the ABI: the program is no longer an input.

Register and coop wrappers

Register — one shot per thread, statevector in VGPRs

#define V2_REG_MAX_AMP 16
__attribute__((amdgpu_kernel, visibility("default")))
void clifft_v2_spec(...) {
  u64 shot_id = shot_offset +
    ((u64)v2_bid() * 256ul + __builtin_amdgcn_workitem_id_x());
  if (shot_id >= shots) return;
  V2State st;
  CV2Complex vloc[V2_REG_MAX_AMP];
  CV2Complex sloc[V2_REG_MAX_AMP/2];
  spec_body(&st, vloc, sloc, V2_REG_MAX_AMP, shot_id, ...);
}
No LDS, no barrier, no atomics. The state is automatic storage — which is why §5.5's VGPR saturation was fatal to V1 here and why V2's kernel reports vgpr_spill = 0.

Coop — one workgroup per shot, everything in LDS

extern __attribute__((address_space(3))) CV2Complex lds_v[V2_MAX_AMP];
extern __attribute__((address_space(3))) CV2Complex lds_red_scratch[V2_SCRATCH_AMP];
extern __attribute__((address_space(3))) V2State lds_state;

void clifft_v2_spec(...) {
  u64 shot_id = shot_offset + (u64)v2_bid();
  if (shot_id >= shots) return;
  spec_body((V2State*)&lds_state, (CV2Complex*)lds_v,
            (CV2Complex*)lds_red_scratch, ...);
}
256 threads cooperate on one shot. The shared objects are declared address_space(3) and cast at the call — spec_body itself is address-space agnostic, which is how one body serves all three tiers.

Global — a persistent pool draining an atomic counter

void clifft_v2_spec(..., CV2Complex* global_v, CV2Complex* global_scratch, u64* work_counter) {
    u32 t = v2_tid(), slot = v2_bid();
    const u64 amp_capacity = 8192ull;                    // <- 1<<peak_rank, a constant
    CV2Complex* v       = global_v       + (u64)slot * amp_capacity;
    CV2Complex* scratch = global_scratch + (u64)slot * (amp_capacity >> 1);
    for (;;) {
        if (t == 0) lds_shot = __atomic_fetch_add(&work_counter[0], 1UL, __ATOMIC_RELAXED);
        v2_barrier();
        u64 batch_shot = lds_shot;
        if (batch_shot >= shots) return;
        spec_body((V2State*)&lds_state, v, scratch, (u32)amp_capacity, shot_offset + batch_shot, ...);
        v2_barrier();
    }
}
The grid does not scale with shots
A fixed resident pool loops until the counter is drained. One dispatch for 10,000 shots, not 10,000 workgroups.
amp_capacity is a literal
8192ull — not a kernel argument. Every slice-offset multiply becomes a shift, and every bound is a compile-time constant. That is §7.5 acting on the addressing arithmetic.
Two barriers per shot
One after the counter fetch (publish lds_shot), one after the body (protect the next iteration's write). §11.2 is what happens when those are execution-only.

The persistent kernel

The resident pool is sized from an HBM budget, not from the rank cap

v2_kernel.cc:436-445:

const uint64_t amp = 1ull << flat.peak_rank;
const uint64_t bytes_per_wg = amp * sizeof(GpuComplex) + (amp / 2) * sizeof(GpuComplex);
const uint64_t budget = 32ull << 30;  // 32 GB
uint64_t wgs = budget / bytes_per_wg;
if (wgs < 1) wgs = 1;               // rank 26+: at least one resident wg
if (wgs > 2048) wgs = 2048;
global_grid_wgs = (uint32_t)wgs;
// Prefer a multiple of the XCD count when the budget allows it, so the
// resident pool spreads evenly; never inflate past the budget.
if (global_grid_wgs > kNumXCDs) global_grid_wgs -= global_grid_wgs % kNumXCDs;
GpuComplex is {float re; float im;} — 8 bytes (gpu_types.h:38-41) — so bytes_per_wg is a slice plus a half-size scratch: 12 bytes per amplitude. Four clauses, each doing distinct work: the budget divide, a floor of 1 so rank 26 is possible rather than fast, a ceiling of 2,048, and a round-down to a multiple of kNumXCDs = 8 so the pool spreads across the device's eight compute dies.
