Every design decision downstream — the tiers, the specialization classes, the f32/f64 gap, even the noise regression — follows from the structure of one object.

The factored state

clifft does not carry a dense statevector over all N qubits (svm.h:92-103):

|psi> = gamma · U_C · P · ( |phi>A ⊗ |0>D )
symbolwhat it isstorage
gammaglobal scalar: phase + deferred normalizationone complex scalar
U_Cthe Clifford part, tracked symbolicallyimplicit in the frame
Pa Pauli frame — one X bit and one Z bit per qubit2 × ⌈N/64⌉ words
|phi>Athe active subspace: dense statevector over k qubits 2^k complex amplitudes
|0>Dthe dormant qubits, provably in the computational basis nothing
The whole performance story lives in k, the active rank. A pure-Clifford circuit never grows it: every gate is a frame update, 2^k = 1, and simulation is polynomial. Each non-Clifford operation may promote a dormant qubit, k → k+1, doubling the dense array. Each active measurement collapses it back.

The factored state, drawn

The peak rank of a compiled circuit — the maximum k over the whole program — determines both the memory footprint and, as §3 shows, which GPU execution strategy is even viable.

The count matters later: 41 arms that a CPU interpreter must dispatch over, and that a specialized kernel never dispatches over at all.

The 32-byte instruction — all a specializer can see

struct alignas(32) Instruction {
    Opcode   opcode;      // offset 0
    uint8_t  _reserved;   // offset 1
    uint8_t  flags;       // offset 2
    uint8_t  _pad;        // offset 3
    uint16_t axis_1;      // offset 4  virtual axis
    uint16_t axis_2;      // offset 6  virtual axis 2
    union {               // offsets 8..31
      struct{ double   weight_re, weight_im;      } math;      // A
      struct{ uint32_t classical_idx, expected_val; } classical; // B
      struct{ uint32_t cp_mask_idx, condition_idx;  } pauli;     // C
      struct{ uint64_t mask;                      } multi_gate;// D
      struct{ uint32_t cp_idx;                    } u2;        // E
      struct{ uint32_t cp_idx;                    } u4;        // F
      struct{ uint32_t cp_exp_val_idx, exp_val_idx; } exp_val;  // G
      uint8_t raw[24];
    };
};
static_assert(sizeof(Instruction) == 32, "exactly 32 bytes");
Why 32
Two instructions land in one 64-byte cache line (backend.h:92). Asserted, not assumed (:163).
Variants E, F, G
Their entire payload is a uint32_t index. Anything that does not fit in 24 bytes — fused 2×2 and 4×4 unitaries, N-bit Pauli masks, noise-channel tables — lives in a side ConstantPool.
The specialization limit, encoded in a struct
The index folds to an immediate. The contents stay in a device buffer. A specializer can eliminate the load of the index; it cannot eliminate the load of the matrix. §7's S6 and S8 measure exactly this ceiling.

The CPU already knew dispatch was the enemy

The CPU reference uses a computed-goto threaded dispatch table (svm_kernels.inl:2191-2196), sized to 256 so each of the 41 opcodes gets its own indirect-branch history entry:

// Threaded dispatch table (computed gotos) gives each opcode its own
// indirect-branch history entry, dramatically improving prediction.
// Sized to 256; designated initializers map enums directly to labels.
static const void* dispatch_table[256] = {
    [static_cast<uint8_t>(Opcode::OP_FRAME_CNOT)] = &&L_OP_FRAME_CNOT,
    [static_cast<uint8_t>(Opcode::OP_FRAME_CZ)]   = &&L_OP_FRAME_CZ,
    ...
};
That comment is the thesis of this whole report, stated by the CPU backend years earlier. Dispatch is a first-class cost, and it is worth writing non-portable code to attack — the #if defined(__GNUC__) guard exists because someone decided the win justified maintaining a portability fallback.
On a CPU: make dispatch cheaper
Fight it with branch-target prediction. Give each opcode its own history entry.
On a GPU: that option does not exist
There is no branch predictor to help. A wavefront hitting an indirect branch does not predict — it serializes across whatever divergent targets its 64 lanes want. Removing dispatch entirely is the only move available. It is worth 2.8–9.1× on the scalar unit (§14.2).

The PRNG must be bit-exact — and that is a load-bearing constraint

CPU reference — svm.h:148-150
// CRITICAL: Do NOT use std::uniform_real_distribution
// -- its output is implementation-defined and varies
// across compilers (GCC vs Clang vs MSVC).
[[nodiscard]] double random_double() {
  return (double)(rng_() >> 11) * 0x1.0p-53;
}
V2 device code — v2_ops.h:155-177
static inline u64 rng_next(u64* s) {
  u64 result = v2_rotl64(s[0] + s[3], 23) + s[0];
  u64 t = s[1] << 17;
  s[2] ^= s[0]; s[3] ^= s[1]; s[1] ^= s[2]; s[0] ^= s[3];
  s[2] ^= t;    s[3] = v2_rotl64(s[3], 45);
  return result;
}
static inline double rng_uniform(u64* s) {
  return (double)(rng_next(s) >> 11) * 0x1.0p-53;
}
What is deliberately not there
No ocml call. No device-library dependency. No fast-math-sensitive arithmetic. The conversion is an integer shift and an exact power-of-two multiply, so it is bit-identical on any target with IEEE doubles.
The one place "share the source" failed
The CPU side is C++; the device side is freestanding C23. The sequence had to be transliterated and then verified by output comparison rather than shared — down to the rotate constants.
The consequence — the key to §12
Any divergence in how many random numbers a backend draws is unrecoverable. Not "slightly different results": the two streams decorrelate permanently from the first extra draw.

A branch taken differently, an early-exit that skips a draw, a dust threshold that clamps on one side and rolls on the other — all of these are the same bug.

Three properties that determine everything downstream

1. The hot loop is a butterfly, not a GEMM
ARRAY_U2 applies a 2×2 complex matrix to 2^(k−1) amplitude pairs; ARRAY_U4 a 4×4 to 2^(k−2) quadruples.

There is no matrix multiply here — which is why SQ_INSTS_MFMA is 0.0 in every counter block collected, all 52 backend×circuit cells of job 50793, none missing.

The matrix cores, the headline feature of this chip, are simply not part of this story.
2. The working set spans four orders of magnitude
At peak rank 0 the "statevector" is one complex number. At rank 24 it is 16.7 million.

No single parallelization strategy is right for both. That is the entire origin of the tier system (§3.2) — and the reason a specializer has something to decide at all.
3. Shots are parallel; each shot is sequential
A shot is a walk through the bytecode with a private PRNG stream. The parallelism is across shots; the per-shot work is a dependent chain.

That sets a hard ceiling on what any amount of ILP inside one shot can buy — and it is why the register tier packs shots into lanes rather than trying to widen one shot.
